# OpenEval v0.2.0

Interactive analytics, source-qualified transcript search, watchable evaluations,
saved experiments and calibration, and a simpler local installation flow.

## Install

Node 22 and npm 10 are required.

```bash
git clone --branch v0.2.0 --depth 1 https://github.com/RasputinKaiser/OpenEval.git
cd OpenEval
npm run setup
npm run open
```

Open http://127.0.0.1:3000. No API key is required to inspect local transcripts.
Launching agent evaluations and optional LLM judging use your configured agents
and may incur inference charges.

Existing installations: stop the server and evaluations, preserve local edits,
back up data, fetch tags, switch to `v0.2.0`, and rerun setup. Settings includes
an on-demand release check, release notes link, and these update instructions.
It does not automatically replace a running server.

## Changes

- Interactive activity/usage charts, shared date filters, pinned inspections, and
  matching-session navigation with explicit measurement provenance.
- Whole-session transcript search, exact-message windows, tool pairing, encrypted
  revision-bound cursors, and clearer reasoning/content presentation.
- Bounded local readers for Kimi, DeepSeek, compatible OpenCode/ZCode databases,
  and Grok Markdown exports. [Exact formats and limitations](../interactive-analytics-transcripts.md#source-coverage).
- Five watchable reference cases and isolated artifact preview controls; 40 cases
  total, with deterministic checks, oracle solutions, and known-bad fixtures.
- Correct weighted evaluation thresholds and infrastructure-failure handling.
- Saved experiment snapshots and calibration references/observations with explicit
  human, synthetic, missing, and incomparable evidence.
- Responsive Evaluate navigation, clearer setup/case criteria, accessible chart
  inspections, reduced motion, light/dark typography and contrast refinements.
- Locked-dependency setup, SQLite binding verification, and loopback startup.

## Verification boundaries

The release gate runs typecheck, lint, tests, self-tests, strict accuracy checks,
the public-file audit, and a production build. Deterministic/oracle/known-bad
checks do not establish provider-backed agent success or visual quality. Optional
paid LLM checks remain gated; unsupported trace/visual/judge evidence remains
Unknown. Desktop browser checks and narrow-layout emulation do not establish
real-device or full assistive-technology coverage. Windows native dependencies
and shell graders are not validated; use the documented platform guidance.

The build-worker experiment showed no reliable speedup and was reverted. No
build performance improvement is claimed for that experiment.
